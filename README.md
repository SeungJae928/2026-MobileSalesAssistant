# 영업 이동 비서

> 주행은 자동으로, 방문 내용은 도착할 때 음성 한마디로 기록해 **국세청 업무용승용차 운행기록부**와 **영업 방문일지**를 함께 만드는 Pleos Connect 앱

영업 담당자는 하루에 여러 거래처를 차로 돌며, 퇴근 후 운행기록부와 방문일지를 따로 정리합니다.
이 앱은 차량 신호로 출발·도착을 직접 판단하고, 도착하면 "방문 기록을 남길까요?"라고 먼저 묻습니다.
운전자는 화면을 거의 만지지 않습니다.

## APK

| 항목 | 내용 |
| --- | --- |
| 파일 위치 | [`apk/방승재_영업이동비서_release.apk`](apk/) |
| 패키지 | `com.salesdrive` |
| 버전 | 0.1.0 (versionCode 1) |

공개 저장소에 올리는 APK라 Pleos 앱 등록 정보를 넣지 않았습니다. 음성 인식은 On-device 모드로, 방문 내용 정리는 규칙 기반으로 동작합니다.

## 테스트 환경

| 항목 | 내용 |
| --- | --- |
| 에뮬레이터 | **Pleos Connect v2.1.0** (Android Automotive, API 34, x86_64) |
| 화면 규격 | **2560 × 1440**, 160 dpi (가로형) |
| 개발 도구 | Android Studio, JDK 17, Gradle 8.14 / AGP 8.10, Kotlin 2.1 |
| SDK | compileSdk 35, minSdk 28 |

에뮬레이터 설치는 Pleos 개발자 문서의 Connect SDK 에뮬레이터 가이드를 따릅니다.

## 설치 방법

### 1. APK로 설치 (권장)

에뮬레이터를 켠 뒤 저장소 루트에서 실행합니다.

```bash
adb install -r "apk/방승재_영업이동비서_release.apk"
```

앱 목록에서 **영업 이동 비서**를 실행합니다.

### 2. 소스에서 빌드

```bash
git clone https://github.com/SeungJae928/2026-MobileSalesAssistant.git
cd 2026-MobileSalesAssistant
./gradlew :app:installDebug
```

`local.properties`에는 Android SDK 경로(`sdk.dir`)만 있으면 빌드됩니다. Android Studio로 열면 자동으로 만들어집니다.

### 3. 필요한 설정

| 설정 | 방법 | 하지 않으면 |
| --- | --- | --- |
| 권한 | 처음 실행할 때 속도·위치 권한을 허용 | 속도는 기어로 대신 판단하고, 위치는 빈칸으로 기록 |
| 시간대 | 에뮬레이터 설정 → 날짜 및 시간 → 시간대를 **서울**로 변경 (기본값은 미국 서부) | 기록 시각이 한국 시각과 다르게 보임 |
| 내 정보 | 앱의 **내 정보** 탭에서 성명·부서·차량번호 입력 | 홈에 입력 안내가 뜨고, 운행기록부 머리말이 비어 있음 |
| Pleos 앱 등록 정보 (선택) | `local.properties`에 아래 두 값을 넣고 디버그 빌드(`installDebug`) | 음성 인식은 On-device로 동작하고, 방문 내용은 규칙 기반으로 정리 |

```properties
pleos.clientId=<Pleos Playground 앱 Client ID>
pleos.clientSecret=<Pleos Playground 앱 Client Secret>
```

현재 시간대 확인: `adb shell getprop persist.sys.timezone`

## 기능별 사용법

화면 왼쪽에 **홈 · 운행기록부 · 일정 · 내 정보 · 신호 확인** 탭이 있습니다.

### 1. 처음 설정 — 내 정보

1. **내 정보** 탭을 엽니다.
2. 성명·부서와 이 차량의 자동차등록번호·차종·상호를 입력하고 **저장**을 누릅니다. 이 값은 운행기록부 머리말에 들어갑니다.
3. (선택) **시트 자세**에서 운전자 프리셋 번호를 고르면, 시동을 켤 때 기어 P·정차 상태에서 그 자세를 한 번 불러옵니다.
4. (선택) **화면 테마**에서 라이트·다크를 고르면 바로 적용됩니다.

운전자는 차량 화면 오른쪽 위의 차량 프로필로 구분합니다. 별도 로그인은 없고, 기록은 프로필마다 따로 저장됩니다.

### 2. 출발 전 — 홈

- **이번 주행 목적**에서 업무·출퇴근·개인 중 하나를 고릅니다. 고르지 않으면 업무로 기록하고, 도착한 뒤 음성으로 바로잡을 수 있습니다.
- 오늘 주행, 이번 달 주행거리와 업무 비율, 다가오는 일정을 한 화면에서 봅니다.
- 시동을 켜면 오늘 남은 일정을 음성으로 한 번 알려 줍니다. ("오늘 일정이 2건 있습니다. 첫 일정은 …")

### 3. 주행 — 자동 기록

따로 누를 버튼이 없습니다.

1. 기어를 D에 두고 출발하면 기록이 시작되고, 어떤 화면에 있든 **주행 기록 중** 화면으로 바뀝니다. 주행 중에는 다른 화면을 조작할 수 없습니다.
2. 신호 대기처럼 잠깐 멈춘 것은 정차로 보지 않습니다. 기어 P나 주차브레이크가 **30초** 이상 유지돼야 정차로 확정합니다.
3. 정차하면 도착 여부를 내비 목적지 도착 → 운전자 확인 → 시동 끔 순으로 판단합니다. 휴게소처럼 들렀다 다시 출발하면 경유지로 남깁니다.
4. 주행거리는 계기판 누적 주행거리(Odometer)를 그대로 씁니다.

### 4. 도착 — 음성 방문 기록

1. 도착이 확정되면 앱이 묻습니다. "OO 도착하셨네요. 방문 기록을 남길까요?"
   기다리지 않고 바로 남기려면 정차한 뒤 홈의 **방문 기록** 버튼을 누릅니다. 방문이 아닌 정차라면 **건너뛰기 (경유)**를 누르면 경유지로 남습니다.
2. 전에 방문한 곳이면 먼저 지난 방문 요약과 후속 조치를 읽어 줍니다.
3. 방문 내용을 말로 답합니다.
   예: "A상사 김부장 만나서 납품 미팅했고, 견적은 다음 주 화요일까지 보내기로 했어"
4. 답한 원문을 그대로 저장하고, **거래처 · 담당자 · 요약 · 후속 할 일 · 후속 날짜**로 정리합니다. 후속 날짜가 있으면 일정 탭에 후속 조치로 표시됩니다.

### 5. 차 안 음성 명령 — Gleo

차량 음성 비서(Gleo)에 말하면 앱을 열지 않아도 기록됩니다. 앱 이름 없이 문장으로 말하면 됩니다.

| 하고 싶은 일 | 예시 |
| --- | --- |
| 방금 한 방문 기록 | "C물산 박과장 만나서 신제품 소개했어" |
| 앞으로의 일정 추가 | "다음 주 수요일 오후 3시에 C물산 미팅 일정 잡아줘" |

"영업 비서"라고만 말하면 Gleo가 앱을 여는 명령으로 처리합니다. 기록하려면 내용을 함께 말하세요.

### 6. 기록 확인·수정 — 주행 상세

홈이나 운행기록부에서 주행 하나를 누르면 상세 화면이 열립니다.

- 출발·도착·경유지, 계기판 주행거리와 목적을 봅니다.
- 방문 기록의 원문과 정리 결과를 확인하고 **수정**할 수 있습니다. **다시 분석**을 누르면 원문을 다시 정리합니다.
- 음성으로 남기지 못했다면 **+ 방문 기록 추가**로 직접 적습니다.
- **◀ 목록**으로 돌아갑니다.

### 7. 일정 — 달력

- 월 단위 달력에 일정과 방문 후속 조치가 표시됩니다. ◀ ▶로 달을 옮기고, **이번 달**로 돌아옵니다.
- 날짜를 누르면 오른쪽에 그날의 거래처·담당자·방문 요약·후속 조치가 나옵니다.
- 일정은 **지우기**로 삭제합니다.
- 일정이 있는 거래처에 도착하면 도착 안내와 함께 그 일정을 알려 줍니다.

### 8. 운행기록부 — CSV 내보내기

1. **운행기록부** 탭에서 ◀ ▶로 달을 고릅니다.
2. 주행 횟수, 총 주행거리, 일반업무·출퇴근·개인 거리와 업무사용비율을 확인합니다.
3. **CSV 내보내기**를 누르면 국세청 양식 순서의 파일을 저장합니다.
   저장 위치: `다운로드/영업이동비서/운행기록부_YYYY-MM.csv`

### 9. 신호 확인 — 시연 주행 재생

- 앱이 읽고 있는 시동·기어·속도·주차브레이크·주행거리·위치 신호와 현재 기록 상태, 최근 주행을 보여 줍니다.
- **▶ 시연 주행 재생**을 누르면 출발 → 약 30km 주행 → 거래처 도착 → 주차 → 음성 질문까지 매번 같은 순서로 재생합니다. 차를 움직이지 않고 전체 흐름을 볼 수 있습니다.
- **■ 시연 종료 (실제 신호로)**를 누르면 실제 차량 신호로 돌아갑니다.

## 에뮬레이터에서 테스트하기

가장 빠른 방법은 **신호 확인** 탭의 **▶ 시연 주행 재생**입니다. 차량 신호를 직접 바꿔 보려면 에뮬레이터의 **Virtual Console**을 씁니다.

1. 기어 D, 속도를 올리면 → **주행 기록 중** 화면
2. 속도 0, 기어 P(또는 주차브레이크)로 30초 유지 → 도착 판단과 음성 질문
3. 음성으로 방문 내용 답하기 → 홈·운행기록부에서 주행과 방문 기록 확인

Virtual Console의 전원 On/Off는 시동 신호를 바꾸지 않습니다. 시동 시 동작(오늘 일정 안내, 시트 불러오기)은 앱을 다시 실행해 확인합니다.

## 구조

```
app/src/main/java/com/salesdrive/
├── vehicle/   Pleos SDK·AAOS 차량 속성·위치를 앱 공통 신호(VehicleSnapshot)로 변환 — SDK 의존은 여기만
├── trip/      트립 상태머신, 상태 전이를 DB에 기록, 포그라운드 서비스
├── navi/      NaviHelper 목적지·도착 이벤트, 휴게소 정차 판단
├── voice/     TTS 질문, STT 응답, LLM/규칙 기반 방문 파서, 도착·오늘 일정 안내
├── gleo/      Gleo 음성 명령(방문 기록, 일정 추가) 수신
├── profile/   시동 시 시트 메모리 불러오기
├── data/      Room DB(Trip, TripStop, Visit, Schedule, DriverProfile, Vehicle)와 저장소
├── export/    운행기록부 CSV
└── ui/        Jetpack Compose 화면(홈, 운행기록부, 일정, 내 정보, 주행 상세, 기록 중)
```

```
IDLE ─시동─▶ READY ─출발─▶ DRIVING ◀─재출발/정지─▶ PAUSED ─주차 30초─▶ STOPPED ─도착 확정─▶ ASKING ─응답─▶ READY
                                                                         └─다시 출발─▶ DRIVING (경유지로 기록)
```

자세한 설계는 [PROJECT_GUIDE.md](PROJECT_GUIDE.md)를 참고하세요.
